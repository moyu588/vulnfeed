# 生产升级与运维备忘（vulnfeed-deploy）

> 适用场景：`vulnfeed/` 代码更新后，重新构建镜像并替换生产容器。
> 结论：**重建镜像不会触碰生产数据**——数据在 `vulnfeed-deploy/data/`（postgres 的宿主机 bind mount），升级只替换 `vulnfeed` 应用容器。风险在"新代码如何与数据交互"，靠流程防护。

## 1. 部署结构速览

```
vulnfeed-deploy/
├── data/                    ← 生产数据（postgres 数据目录，bind mount）
├── config/config.toml       ← 应用配置（挂载进容器，600）
└── docker-compose.yml       ← vulnfeed 服务只有 image: 没有 build:
      postgres: postgres:14.0 + ./data/ 挂载，端口 127.0.0.1:5432
      vulnfeed:  vulnfeed:latest + config.toml 挂载，端口 9000
```

- `docker-compose.yml` 里 `vulnfeed` 服务无 `build:` 段，镜像在源码仓库单独 `docker build`，与数据目录零接触。
- 应用连数据库走 compose 内部网络（`vulnfeed-net`），不走宿主机端口映射，5432 收敛不影响应用。

## 2. 新代码与数据的三个交互点（风险来源）

| # | 交互点 | 说明 | 防护 |
|---|---|---|---|
| 1 | **数据库迁移** | 每次启动自动执行 `sqlx::migrate!("./migrations")`（`src/cli.rs`），**只进不退** | 升级前 diff `migrations/`；非增量迁移上线前必须想好回滚策略 |
| 2 | **业务逻辑改动** | 新代码的读写逻辑 bug 可能改坏数据（如误改 `pushed` 状态、误删记录） | 升级前 `pg_dump` 备份 |
| 3 | **配置兼容性** | 新代码若新增必填配置项，旧 `config.toml` 可能导致启动失败（服务挂但数据无损） | 升级前 diff `dev/config.toml.example` |

## 3. 标准升级流程

```bash
# ① 逻辑备份（不停机，最可靠）
mkdir -p /openclaw/github/vulnfeed-deploy/backup
cd /openclaw/github/vulnfeed-deploy
docker compose exec -T postgres pg_dump -U postgres vulnfeed \
  > backup/vulnfeed-$(date +%Y%m%d-%H%M%S).sql

# ② 保留旧镜像作为回滚点
docker tag vulnfeed:latest vulnfeed:rollback-$(date +%Y%m%d)

# ③ 升级前检查：有无新迁移 / 新配置项（硬性关卡）
cd /openclaw/github/vulnfeed
git diff main..HEAD -- migrations/ dev/config.toml.example

# ④ 构建新镜像
docker build -t vulnfeed:latest -t vulnfeed:$(date +%Y%m%d) .

# ⑤ 只重启应用容器（postgres 不动）
cd /openclaw/github/vulnfeed-deploy
docker compose up -d vulnfeed

# ⑥ 验证
docker logs vulnfeed-deploy-vulnfeed-1 2>&1 | grep -iE "migration|error" | head
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:9000/   # 期望 200
```

## 4. 回滚（约 30 秒）

```bash
docker tag vulnfeed:rollback-<日期> vulnfeed:latest
cd /openclaw/github/vulnfeed-deploy && docker compose up -d vulnfeed
```

**回滚限制**：若新镜像带"非增量"迁移（删列/改列类型/改表）且已成功启动，旧镜像可能因 schema 不匹配起不来。只要迁移保持增量式（现有 4 个迁移均为 `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN`），回滚永远安全。

数据级回滚（逻辑备份恢复，破坏性操作前先停应用容器）：

```bash
docker compose stop vulnfeed
docker compose exec -T postgres psql -U postgres vulnfeed < backup/vulnfeed-xxx.sql
docker compose start vulnfeed
```

## 5. 可选：影子环境演练

复制一份 `data/` 目录，用临时 compose（改容器名与端口）起一套隔离环境先跑新镜像，确认迁移和功能正常后再动生产。
